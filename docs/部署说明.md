# 砚衡升学（zytb）部署说明

当前约定（无独立业务服务器）：

| 角色 | 环境 | 怎么跑 |
|---|---|---|
| **开发** | Windows 本机 | `mvn package` + `start-all.ps1`（profile=`dev`） |
| **生产** | **Mac Docker Desktop** | Jenkins 打 `linux/arm64`+`prod` 镜像 → Mac `docker load` → `docker-compose.mac.yml` |

仓库：

- 后端：https://gitee.com/sh0818/zytb-java.git
- 前端：https://gitee.com/sh0818/zytb-vue.git

> 下文「虚拟机 / Linux host compose」仅作历史备用；日常生产以 **第十二节 Mac** 为准。

---

## 一、虚拟机建议规格

| 场景 | CPU | 内存 | 磁盘 |
|---|---|---|---|
| 中间件已在别机，本机只跑应用 | 4 核 | 8GB | 40GB+ SSD |
| 本机一并跑 MySQL + Redis + Nacos | 4～8 核 | **16GB** | 100GB+ SSD |

开放端口：对外 **80**（前端）；后端 8800–8806 建议仅本机。MySQL/Redis/Nacos 勿对公网裸开。

---

## 二、先准备中间件

需要：

1. **MySQL 8**：库名 `zytb`，utf8mb4  
2. **Redis**：供登录 token、验证码  
3. **Nacos 2.x**：生产命名空间 **`hbbxl`**（与本地测试 `hbbxl-test` 分开）  
4. **MinIO**（可选）：校徽已多数指向 `http://81.70.105.12:9010/hbbxl/logos/...`；若 VM 访问不到该地址，需保证可达或重新迁 logo

### 导入表结构与数据

在能连上目标 MySQL 的机器执行（按序）：

```text
docs/sql/rebuild/01_schema.sql
docs/sql/rebuild/02_base_data.sql
docs/sql/rebuild/03_aspiration.sql
docs/sql/rebuild/04_crawl.sql
docs/sql/rebuild/05_hebei_fill.sql
docs/sql/rebuild/06_sys_config.sql
docs/sql/rebuild/07_sys_log.sql
```

业务数据（院校、招生专业、分数线等）若本地已有完整 `zytb`，可用 `mysqldump` 迁到虚拟机，比只建空表更省事。

### Nacos 配置要点

- 命名空间：`hbbxl`
- 各服务 `prod` 下数据源应指向 **虚拟机（或内网）MySQL 的 zytb**，不要仍指向开发机 `127.0.0.1`
- Redis 指向可用的 Redis 实例
- 服务注册发现地址改为虚拟机能访问的 Nacos

容器启动参数：`SPRING_PROFILES_ACTIVE=prod` → 使用 `application-prod.yml`（Mac：同网络容器名 + 命名空间 `hbbxl`）。改 yaml 后须重新打包镜像；容器名/密码用 `.env.mac` 覆盖。

## 五、构建镜像（二选一）

### 方式 A：Mac 本机构建（随时可用）

```bash
# 先 clone 前后端到同级目录，例如 ~/work/zytb-java 与 ~/work/zytb-vue
cd ~/work/zytb-java
git pull
cd ~/work/zytb-vue && git pull

cd ~/work/zytb-java
bash docker/build-mac.sh "$(pwd)" "$(cd ../zytb-vue && pwd)"
```

会打出 `linux/arm64` + `prod` 的 8 个镜像，然后用 `docker-compose.mac.yml` 启动。

### 方式 B：GitHub Actions → GHCR（推荐的云端打包）

1. 把 `zytb-java`、`zytb-vue` 推到 GitHub（可与 Gitee 双远程）  
2. 仓库 Settings → Actions → Workflow permissions → **Read and write**  
3. 推送 `master` 或手动 Run workflow，产物如 `ghcr.io/<用户名>/hbbxl/gateway:latest`  
4. Mac 登录并拉取：

```bash
echo <GitHub_PAT> | docker login ghcr.io -u <GitHub用户名> --password-stdin
# .env.mac:
# REGISTRY_PREFIX=ghcr.io/<GitHub用户名>/
docker compose -p hbbxl -f docker-compose.mac.yml --env-file .env.mac pull
docker compose -p hbbxl -f docker-compose.mac.yml --env-file .env.mac up -d
```

PAT 需勾选 `read:packages`（拉）/ `write:packages`（若本机还要推）。

### 方式 C：Jenkins（可选；服务器不可用可跳过）

流水线打 arm64 并归档 tar；Mac `docker load` 后启动。

> 注意：不要用旧的 `docker/build-and-deploy.sh`（魄力学习服务清单）。Mac 请用 `build-mac.sh`。

## 六、启动后端（Compose）

```bash
cd /opt/hbbxl/zytb-java/docker
cp .env.example .env   # 按需改 REGISTRY_PREFIX / SPRING_PROFILES_ACTIVE=prod

docker compose -p hbbxl --env-file .env -f docker-compose.yml up -d --pull never
docker compose -p hbbxl ps
```

健康检查示例：

```bash
curl -sf http://127.0.0.1:8800/actuator/health
curl -sf http://127.0.0.1:8801/actuator/health
# …8802～8806 同理
```

Compose 使用 **host 网络**：容器直接占用宿主机 8800–8806。

---

## 七、启动前端（Compose 未包含 web，需单独跑）

```bash
docker run -d --name hbbxl-web --restart unless-stopped --network host \
  -e NGINX_PORT=80 \
  hbbxl/web:latest
```

浏览器访问：`http://<虚拟机IP>/`  
前端通过 `/api` 反代到本机 `127.0.0.1:8800`（见 `zytb-vue/nginx.conf`）。

若 80 被占用，可改：

```bash
docker run -d --name hbbxl-web --restart unless-stopped --network host \
  -e NGINX_PORT=8088 \
  hbbxl/web:latest
```

然后访问 `http://<虚拟机IP>:8088/`。

## 十、常见问题

| 现象 | 处理 |
|---|---|
| 网关通、业务全超时 | Nacos 里注册的实例 IP 不是虚拟机可达地址，重启全部服务重新注册 |
| 连错库 / Unknown database | 改数据源后未重新 `package`+`docker build`，旧 jar 仍进旧镜像 |
| 校徽裂图 | MinIO `81.70.105.12:9010` 虚拟机访问不到；打通网络或改 `img_url` |
| 登录验证码失败 | Redis 不通或密码/库号不对 |
| Windows 虚机/桌面 Docker | host 网络行为与 Linux 不同，**请用 Linux 虚拟机** |

## 十一、与当前开发环境的关系

| 项 | 本地开发 | 虚拟机生产 |
|---|---|---|
| Profile | `dev` / 命名空间 `hbbxl-test` | `prod` / `hbbxl` |
| MySQL | 常为开发机 `127.0.0.1/zytb` | 虚机或内网 MySQL |
| Nacos/Redis | 现多用 `81.70.105.12` | 可复用或自建，须虚机能访问 |
| 启动 | `start-all.ps1` | Docker Compose + web 容器 |

## 十二、Mac Docker Desktop（M4 等 Apple Silicon）= 生产环境

约定：

| 环境 | 机器 | Profile | 中间件 |
|---|---|---|---|
| **开发** | Windows 本机 | `dev`（`start-all.ps1`） | MySQL=`127.0.0.1`；Nacos/Redis 仍按 `bootstrap.yml`（现为远程或本机开发配置） |
| **生产** | Mac Docker Desktop | `prod` | 中间件与业务同网 `hbbxl-net`，用容器名（见 `application-prod.yml`） |

生产默认走 **同一 Docker 网络 `hbbxl-net` + 容器名**（`mysql` / `redis` / `nacos` / `minio`），**不用** `host.docker.internal`。  
先把中间件容器 `docker network connect hbbxl-net <容器名>`；若桌面里名字不是上述默认，改 `.env.mac`。  
账号默认：Nacos `nacos/nacos` 命名空间 `hbbxl`；MySQL `root/root` 库 `zytb`；Redis 无密码；MinIO API `minio:9000`，浏览器 `127.0.0.1:9010`。

**不要用** Linux 的 `docker-compose.yml`（`network_mode: host`）。Mac 用：

- `docker/docker-compose.mac.yml`（默认 `SPRING_PROFILES_ACTIVE=prod`）
- `docker/.env.mac.example` → 复制为 `.env.mac`

### 步骤摘要

1. 确认中间件已映射到 Mac 端口（常见：3306 / 6379 / 8848 / 9010 或 9000），浏览器或本机客户端能连上。  
2. MySQL 建库 `zytb` 并导入数据（`mysqldump` 或 `docs/sql/rebuild/`）。  
3. Nacos 建命名空间 **`hbbxl`**（生产；与 `application-prod.yml` / `.env.mac` 一致）。  
4. **在 Mac 上重新构建镜像（推荐 arm64）**：须带 `prod`，使 jar 内 `application-prod.yml` 生效：

```bash
# 后端
cd zytb-java
docker run --rm --platform linux/arm64 \
  -v "$PWD":/src -w /src -v hbbxl_m2:/root/.m2 \
  -v "$PWD/docker/maven-settings.xml":/opt/settings.xml:ro \
  maven:3.9-eclipse-temurin-17 \
  mvn -q -s /opt/settings.xml -DskipTests package

for svc in gateway auth user college score aspiration recommend; do
  cp docker/Dockerfile.backend "hbbxl-$svc/Dockerfile"
  docker build --platform linux/arm64 \
    --build-arg JAR_FILE="target/hbbxl-$svc-1.0.0-SNAPSHOT.jar" \
    -t "hbbxl/$svc:latest" "hbbxl-$svc"
done

# 前端
cd ../zytb-vue
docker build --platform linux/arm64 -t hbbxl/web:latest .
```

5. 启动应用：

```bash
cd zytb-java/docker
cp .env.mac.example .env.mac   # 改密码、端口与你的中间件一致
docker compose -p hbbxl -f docker-compose.mac.yml --env-file .env.mac up -d
```

6. 浏览器打开 `http://localhost/`（或 `.env.mac` 里的 `WEB_PORT`）。

应用通过 **同网络容器名** 访问 MySQL/Redis/Nacos/MinIO；前端经 **`hbbxl-gateway:8800`** 反代 API。

若 Jenkins 只有 `linux/amd64` 镜像，可把 `.env.mac` 里 `DOCKER_PLATFORM=linux/amd64`（靠模拟跑，更慢，不推荐长期用）。
